# Figma 调色 — After Effects 效果插件（v1.0）

把 Figma「图片填充 → 调色」的七项滑杆（曝光 / 对比度 / 饱和度 / 白平衡 / 着色 / 高光 / 阴影）**逐像素精确还原**到 After Effects：不是 LUT 烘焙、不是近似映射，而是直接实现 Figma 画布渲染器那套调色 shader。

| 项目 | 值 |
|---|---|
| 插件名 | **Figma 调色** |
| Match Name（脚本用） | `F2A Figma Image Grade` |
| 分类 | `F2A 插件` |
| 参数 | 曝光、对比度、饱和度、白平衡、着色、高光、阴影（Figma 面板数值 −100 ~ +100，默认 0） |
| 版本 | 1.3.0（PiPL 622593） |
| 二进制 | `FigmaImageGrade.aex`（x64，46,080 B，SHA256 `b16819f997f97b0a2872468cd0a71cb9719230432fdf7625235737a4cabc1861`，`/arch:AVX2` 编译，需要 AVX2 CPU） |
| 构建 | After Effects SDK 27.0 (Windows) + MSVC 19.44 (v143) + MSBuild |
| 已验证宿主 | After Effects 2026（26.0x67），Windows x64，8 bpc，简体中文 UI |
| 多帧渲染 | PiPL 与 `PF_Cmd_GLOBAL_SETUP` 均声明 `PF_OutFlag2_SUPPORTS_THREADED_RENDERING` |

## 1. 为什么用它取代之前的两种做法

`tests/image-filter-study.md` 里记录过两条路，各有硬伤：

| 做法 | 问题 |
|---|---|
| 七项一起代入公式生成 64³ LUT（AE「应用颜色 LUT」） | 精度很高（mean 0.032–0.073），但**一张表对应一组参数**，改一个数就得重新烘表，不能打关键帧 |
| 七个 AE 原生效果＋逐项标定近似 | 可调，但多项叠加后误差 1.86–3.05 / P99 22–51，肉眼可见 |

本插件把**完整公式做成实时效果**：七项滑杆随便改、可以打关键帧、任意时刻精度都在 1 个色阶以内。

## 2. 算法（Figma 126.8.16 画布着色器，见 image-filter-study.md）

逐像素顺序固定，七项都是 `ImagePaint.filters`（−1…+1；编辑器内部饱和度记作 `vibrance`，对比度为 `0.3×contrast`）：

1. **解码**：`linear = encoded ^ 2.2`；
2. **高光/阴影曝光补偿**（用原像素亮度）：`d = Y(linear) − 0.5^2.2`，`amount = d>0 ? highlights : −0.999·shadows`，`ev = exposure + 0.75·d/√(1+4d²)·amount`；
3. **Lab 空间**：白平衡只改 `b*`（+`30·temperature`），着色只改 `a*`（+`30·tint`），对比度只改 `L*`（`c = 0.3·contrast`：负向压缩 `L` 到 `(L−50)·0.2+50`，正向用 20–80 的 S 曲线）；
4. **曝光曲线**：`gain = 10^(2ev)`，`curve(x) = x·gain / (1 + x(gain−1))`，先把颜色 75% 混向自身亮度、再按色度系数 `chroma = 3(1 + Y²·negative/(0.2−negative))` 补偿；
5. **饱和度**：负向向等亮灰混合（`1+s`），正向按 RGB 立方体边界限幅（上限 2 倍）；
6. **编码**：`^(1/2.2)`，逐通道 clip 到 `[0,1]`。

实现细节：

- 全部用 float32 计算；`pow`/`cbrt` 换成 log2/exp2 多项式（相对误差 ~1e-6，远小于 8 位输出精度），单线程约 **9.25 MPix/s**；
- 七项全 0 时直接透传；对比度/白平衡/着色全 0 时跳过 Lab 往返；曝光/高光/阴影全 0 时跳过曝光曲线（和 Figma shader 的分支一致）；
- **Alpha**：AE 把图层自身表示交给效果——直通（straight）素材收到未预乘数据，预乘素材/调整层下方合成收到预乘数据。插件用「颜色值不可能大于 alpha」的采样判据自动识别，直通时直接调色、预乘时先反预乘再调色并重新预乘。这与 Figma「先调直通颜色、再按填充不透明度预乘」完全一致，所以半透明边缘也不会偏。

## 3. 用法

- **加在图片图层上**（最常用）：图层 → 效果 → `F2A 插件 → Figma 调色`，七个滑杆填 Figma 面板上的数（例如 `−17 / 5 / 18 / −26 / 21 / −21 / 13`）。
- **加在调整层上**：作用于下方所有图层的合成结果（做成统一调色的"滤镜层"）。
- 任何滑杆都可以打关键帧；`七项全 0` 就是原图，便于做「调色进出」动画。

## 4. 精度验证

参考实现 = `tests/figma_image_grade.py`（float64 完整公式 + Figma PNG 导出的 12 位量化规则）。该参考实现已在 image-filter-study.md 中与 Figma 导出逐通道核对：全部 8 位色卡 **99.9967% 完全相同、最多差 1 个色阶**。

### 4.1 内核（C++ float32）vs NumPy float64 参考

| 参数组 | 完全相同通道 | 平均误差 | P99 | 最大 |
|---|---:|---:|---:|---:|
| 设计值 [−17,5,18,−26,21,−21,13] | 97.27% | 0.027 | 1 | **1** |
| 极端值 [100,−100,100,−100,100,−100,100] | 98.27% | 0.017 | 1 | **1** |
| 仅饱和度 +60 / 仅曝光 −50 / 暖色 / 混合 / 仅对比度 +70 / 仅高光+30 阴影−40 / 全 −100 | 96.5–98.3% | 0.017–0.035 | 1 | **1** |

9 组参数、4,958 个覆盖全色域的颜色，**全部最大差 1 个色阶**。

### 4.2 AE 实际渲染 vs NumPy 参考

| 用例 | 通道数 | 平均 | P99 | 最大 |
|---|---:|---:|---:|---:|
| 色卡 512²（262,144 色）× 7 组参数 | 786,432 × 7 | 0.016–0.030 | 1 | **1** |

| 半透明图（带渐变 alpha，黑底合成） | 1,440,000 | 0.040 | 1 | **1** |

### 4.3 AE 实际渲染 vs **真实 Figma 导出**（F2A MCP 建节点 → Figma 自身导出 PNG）

| 用例 | 平均 | P99 | 最大 | 完全相同通道 |
|---|---:|---:|---:|---:|
| 色卡 512²（262,144 色），设计值 | **0.0253** | **1** | **1** | **97.475%** |

## 5. 性能（v1.3）

离线内核基准（单线程，`/O2` + `/Oi` + LTCG + `/arch:AVX2`，每组 3 次取中位数）：

| 参数组 | v1.0（标量） | v1.1（SSE2 四像素） | v1.2（AVX2 编译） | v1.3（16/32bpc 也 SIMD） | v1.0 → v1.3 |
|---|---:|---:|---:|---:|---:|
| 8 位 · 设计值（七项都参与） | 9.25 MPix/s ≈ 104 ms/帧 | 20.5 ≈ 46.8 ms | **52.0 ≈ 18.5 ms** | 52.0 ≈ 18.5 ms | **5.6×** |
| 8 位 · 仅饱和度 | 17.4 ≈ 55 ms | 69 ≈ 13.9 ms | **217 ≈ 4.4 ms** | 217 ≈ 4.4 ms | **12.5×** |
| 16/32 位 · 设计值 | 9.7 ≈ 99 ms | 9.7 ≈ 99 ms | 9.7 ≈ 99 ms | **33.4 ≈ 28.7 ms** | **3.45×** |
| 七项全 0 | memcpy 透传 | memcpy 透传 | memcpy 透传 | memcpy 透传 | — |

各版本做过的事：

1. **v1.1-①** 8 位输入解码查表：256 项目录（同一公式生成，数值完全一致），省掉每像素 3 次 `pow`；
2. **v1.1-②** 整条调色链 SSE2 四像素并行：`log2 / exp2 / cbrt / 除法 / clamp` 全部向量化，公式与运算顺序逐项对应标量版；
3. **v1.1-③** 寄存器压力优化：Lab 矩阵行改乘加累积、`__forceinline`（SIMD 从 14.6 → 20.5 MPix/s）；
4. **v1.2** 工程改用 **`/arch:AVX2`** 编译：VEX 三操作数编码让寄存器压力大降 —— **源码一行没改、输出一字不差，单线程再快 2.5 倍**；
5. **v1.3** 16/32 bpc 路径也改成 SSE2 四像素并行（此前只有 8 位是 SIMD）：16 bpc 从 99 ms/帧降到 28.7 ms/帧。

正确性（每次提速都重新验证过）：

- 内核 vs NumPy 参考（Figma shader）：9 组参数、4,958 个覆盖全色域的颜色，**最大差 1 个色阶**；
- SIMD 路径 vs 标量路径：8 位 10 万随机像素 × 6 组参数、16/32 位 8 万随机像素 × 3 组参数，全部**逐位相同**；
- AE 实际渲染：8 位下 v1.3 / v1.2 / v1.1 / v1.0 在 520×520 遮罩复现与 2560×1440 原生两个合成上**逐字节相同**；16 bpc 项目渲染与参考实现**最大差 1 个色阶**。

> **32 bpc 说明**：AE 的 32 bpc 项目若开启「线性化工作空间」，AE 交给效果的是线性值（连不加效果的直通都会被 AE 改写像素），而本效果按 Figma 的 sRGB 编码空间计算，所以 32 bpc 的观感与 8/16 bpc 不同。这与 v1.0 行为一致，不影响 8/16 bpc 的准确性。
>
> 二进制用 `/arch:AVX2` 编译，需要 AVX2 CPU（AE 2026 的系统要求本身即要求 AVX2）。AE 开多帧渲染后按帧并行，实际导出还会再快数倍。

## 6. 用户素材实测（选中图层 505:1201「Circle_Purple」）

Figma 里选中的这一层：520×520 椭圆，图片填充 2560×1440（`scaleMode = FILL`），七项 filters =
`exposure −0.23 / contrast 0.05 / saturation −0.21 / temperature 0.21 / tint −0.26 / highlights 0.19 / shadows −0.28`
（面板值 −23 / 5 / −21 / 21 / −26 / 19 / −28）。

复现方式：`save_image_fills` 取出原始 2560×1440 图 → AE 合成 520×520，图层按 FILL 缩放到 36.1111% 居中、椭圆 alpha 遮罩，效果填同样的七个值。另外把该节点**临时克隆**并清零 filters 导出（导出后已删除克隆，原图层未改动），作为「不调色」的基线。

| 对比（520² 整层，黑底合成） | 平均 | P99 | 最大 | 完全相同 |
|---|---:|---:|---:|---:|
| 未调色基线（Figma ↔ AE） | 0.492 | 4 | 20 | 63.2% |
| **调色后（Figma 原版 ↔ 插件）** | **0.969** | **5** | **51**（几乎全在椭圆抗锯齿边） | 41.9% |
| 椭圆外（透明区） | **0.000** | 0 | 0 | **100%** |

未调色就已经有 0.49 的差，说明这 520² 上的残差主要来自 **Figma 与 AE 的图片缩放算法差异**（2560×1440 → FILL 裁切 924×520）和椭圆边缘抗锯齿，不是调色本身；调色是带对比度/饱和度的非线性映射，会把这种采样差放大 2 倍左右。

把缩放这个变量去掉，在**原始分辨率 2560×1440** 上只看调色：AE 渲染 vs Figma shader 参考实现（11,059,200 个通道）→ **平均 0.031 / P99 1 / 最大 1 / 96.87% 完全相同**。

所以：**调色本身逐通道 ≤1 级**；整层到像素级的差异来自两边图像缩放与遮罩抗锯齿，是"效果之外"的管线差异。

产物见 `user_pick/`：`native_grade_check.json`、`comparison_520.json`、`deep_color_check.json` 保留在仓库里（数值结果）；对照图（`figma_node_520.png`、`ae_repro_520.png`、`side_by_side_520.png`、`diff_*_x10.png`）和复现工程 `UserPick_Comparison.aep` 属于验证产物，不随仓库分发，可用 `ae-plugin/tests/` 下的脚本重新生成。

## 8. 已知限制

- 8 位输出下与 Figma 导出最多差 1 个色阶（量化规则不同，见 4.3），不是算法误差；
- 只覆盖**普通 sRGB 图片填充**的七项调色；Display P3、线性工作空间、HDR 未实测；
- Figma 的多重填充逐层调色、填充不透明度以外的混合行为需另行验证（本插件按「每层调色」语义实现，可直接叠加多个副本模拟多填充）；
- 对比度在 Figma 内部取值范围是 −0.3…0.3（shader 值），本插件滑杆按 API 值 −1…1 映射（0.3×），与 Figma 面板一致。

## 9. 版本历史

- **1.3**：16/32 bpc 路径也改成 SSE2 四像素并行（此前只有 8 位 SIMD）：16 bpc 从 99 ms/帧降到 28.7 ms/帧（3.45×）；16 bpc 渲染与参考实现最大差 1 个色阶，8 位输出与 1.2 逐字节相同。
- **1.2**：改用 `/arch:AVX2` 编译（VEX 编码、寄存器压力下降）：源码未改、输出逐字节不变，单线程再快 2.5 倍；比 v1.0 合计 **5.6×**（仅饱和度 12.5×）。
- **1.1**：渲染性能优化 —— 8 位解码查表 + SSE2 四像素并行 + 寄存器压力优化；1200×800 设计值从 104 ms/帧降到 46.8 ms/帧（2.2×），仅饱和度 55 → 13.7 ms（4.0×）；输出与 1.0 逐字节相同。
- **1.0**：七项 Figma 图片调色作为实时 AE 效果，公式直算（非 LUT）；直通/预乘 alpha 自适应；中文参数名；MFR；与 Figma 导出逐通道最大差 1 色阶。
