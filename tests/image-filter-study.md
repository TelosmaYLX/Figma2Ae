# Figma 图片调色在 After Effects 中的还原验证

2026-11-20，在 Figma 桌面端和 After Effects 26.0x67 中实测。AE 工程为 8 bpc、工作空间 None。输入为 sRGB PNG。原始图片填充的七个值依次为曝光 −0.17、对比度 +0.05、饱和度 +0.18、白平衡 −0.26、着色 +0.21、高光 −0.21、阴影 +0.13。

## 结果

固定调色可以采样成 3D LUT，加在 AE 中的原图上。红车原尺寸 1127 × 677 上，64³ LUT 的不透明像素平均 RGB 通道误差为 0.18，99% 的通道误差在 1 个色阶以内。七个参数可以作为 AE 滑杆驱动原生效果并打关键帧。本次近似方法在重新调色时会产生可见偏差。

| 实验 | 平均 RGB 通道误差 | 99 分位 | 最大 RGB 通道误差 | 最大 Alpha 误差 |
| --- | ---: | ---: | ---: | ---: |
| 七项直接换算到 Lumetri，原尺寸不透明车身 | 5.10 | 25 | 60 | 0 |
| 64³ LUT，原尺寸不透明车身 | 0.18 | 1 | 6 | 0 |
| 64³ LUT，5,897 个半透明边缘像素，黑底合成 | 0.11 | 1 | 2 | 0 |
| 64³ LUT，独立色卡的 16,384 个留出像素 | 0.14 | 1 | 9 | 0 |
| 原图在 AE 缩放至设计稿大小，与所选图层的 570 × 342 导出对比 | 0.72 | 5 | 23 | 21 |

色阶以 0–255 计。RGB 计算每个通道的绝对差。透明图像按相同预乘方式换算至黑底，主体统计排除全透明像素，Alpha 另行比较。设计稿大小一行同时包含缩放、边缘覆盖和颜色的误差。

## 比较方法

- Figma 原生渲染分别覆盖七个滑杆的 −1、−0.5、+0.5、+1、全零、红车设置和另一组组合设置。直接映射使用 Lumetri 曝光 ±5 档、其他滑杆 ±100，饱和度以 100 为中性。另以 4,096 个训练像素，对七个 Lumetri 参数各扫描 101 档，也试了独立曝光度、亮度和对比度、色相/饱和度、阴影/高光。这些设置均未建立可在全范围复用的等价关系。
- 对 64³ 个已知输入颜色应用完整的 Figma 调色，再将 Figma 渲染结果按红色最快变化的顺序写入 .cube。8 位 PNG 中采样点位于整数色阶，写表时重采样到等距网格。AE 使用原生“应用颜色 LUT”。
- 追加的 4096 × 4096 色卡覆盖全部 16,777,216 个 8 位 RGB 值。全零色卡复核与输入一致，重复采集的调色色卡也一致。用完整表离线查色，红车的 576,489 个不透明像素和独立测试图的 32,833 个不透明像素都与 Figma 逐通道相同。本机 AE 使用该 256³ .cube 的尝试输出了原图，工程采用已在 AE 验证的 64³ 表。
- 现行 F2A 导出这张图层所得的 570 × 342 PNG，与该图层的 Figma 导出逐像素一致。现有回归用例还覆盖 Frame 背景填充、保留子层与边框、独立遮罩及关闭效果栅格化时的提示。

## 七个可编辑滑杆

样例工程的“红车 · 七项可调”合成提供七个 AE 原生滑杆，读数为 Figma API 数值的 100 倍。起始值为 −17、5、18、−26、21、−21、13。以红车固定 LUT 还原起始外观，再根据滑杆相对起始值的变化驱动 Lumetri。原值附近使用实测校准，远离原值时使用独立滑杆扫描得到的分段近似。七项全零回到原图。该工程可以离线运行。

下表以红车原尺寸所有可见像素统计。每次只改一项，其余六项保留设计值。每个数字都是一次实际 AE 渲染与相同设置的 Figma 渲染之间的平均 RGB 通道误差。

| 滑杆 | 在原值上减 20 | 在原值上加 20 |
| --- | ---: | ---: |
| 曝光 | 1.06 | 5.44 |
| 对比度 | 1.50 | 1.35 |
| 饱和度 | 5.37 | 0.70 |
| 白平衡 | 3.24 | 2.45 |
| 着色 | 2.73 | 2.11 |
| 高光 | 1.06 | 1.17 |
| 阴影 | 1.11 | 1.05 |

七项同时在原值上加 [9, −10, −15, 11, −7, 12, 8] 时，平均误差为 6.16、99 分位为 47。换到 [23, −11, 42, 21, −12, 34, −19] 时分别为 15.05、77。曝光从 −17 动画到 +3，AE 中点帧与手动设为 −7 的帧完全一致。重新打开 AEP 后，两套合成的起始帧与保存前逐像素相同。

以上结果适用于本次的 8 位 PNG、色彩设置和 AE 版本。P3、线性工作空间、HDR 与多重填充的逐层调色仍需另外验证。

## 复现固定 LUT

在当前源码版 F2A 中选中只有一项可见图片填充的图层。安装仓库 MCP 的 Node 依赖，Python 环境需有 NumPy 和 Pillow。运行下列命令，输出到一个新的 .cube 文件，再在 AE 的原图层上使用“应用颜色 LUT”。

```powershell
node tests/sample-image-filter-lut.cjs red-car.cube
```

脚本创建一张临时色卡，验证无调色读数，复制所选图片填充的 filters，再采样并移除临时图层。可传入第二个参数指定 F2A 文档连接 ID。本次重新运行得到的 262,144 行数值与样例工程使用的 LUT 完全一致。

[Figma ImagePaint.filters](https://developers.figma.com/docs/plugins/api/Paint/) · [Adobe Apply Color LUT](https://helpx.adobe.com/after-effects/desktop/apply-effects-and-animation-presets/list-of-effects/utility-effects.html)

## Figma 原生调色算法

2026-11-20，从 Figma 桌面端 126.8.16 使用的画布渲染器还原。下面的公式适用于普通 sRGB 图片填充。七项都属于 `ImagePaint.filters`，范围是 −1 到 +1，默认值为 0。编辑器内部把饱和度记为 `vibrance`，对比度使用 −0.3 到 +0.3 的范围。从插件 API 读取时，着色器对比度为 `0.3 × contrast`，其余六项使用原值。[Figma ImageFilters](https://developers.figma.com/docs/plugins/api/Paint/#imagefilters)

### 运算顺序

采样后的 RGB 先逐通道做 `RGB^2.2`。用该像素的亮度算出高光和阴影的曝光补偿。随后在 Lab 坐标下改色温、着色和对比度，转回 RGB 并截到 `[0, 1]`。再应用曝光曲线和饱和度，最后做 `RGB^(1/2.2)`。这两个幂函数是调色着色器里的固定变换。颜色空间转换在支持它的渲染分支中另行执行。

`Y(rgb) = dot(rgb, [0.2126, 0.7152, 0.0722])`。下面的 `clip` 逐通道截到 `[0, 1]`，`mix(a, b, t) = a + (b − a) × t`。RGB 和 XYZ 都按列向量运算。

```text
RGB_TO_XYZ = [ 0.4124564   0.3575761   0.1804375 ]
             [ 0.2126729   0.7151522   0.0721750 ]
             [ 0.0193339   0.1191920   0.9503041 ]

XYZ_TO_RGB = [ 3.2404542  -1.5371385  -0.4985314 ]
             [-0.9692660   1.8760108   0.0415560 ]
             [ 0.0556434  -0.2040259   1.0572252 ]

white = [0.95047, 1.0, 1.08883]

# 从原像素亮度计算有效曝光
rgb = inputRGB ^ 2.2
d = Y(rgb) - 0.5 ^ 2.2
weight = highlights if d > 0 else -0.999 * shadows
e = exposure + 0.75 * d / sqrt(1 + 4 * d * d) * weight

# 白平衡改 b*，着色改 a*，对比度只改 L*
fx, fy, fz = ((RGB_TO_XYZ @ rgb) / white) ^ (1/3)
L = 116 * fy - 16
a = 500 * (fx - fy) + 30 * tint
b = 200 * (fy - fz) + 30 * temperature
c = 0.3 * contrast
if c < 0:
    L = mix(L, (L - 50) * 0.2 + 50, -c)
else:
    t = clip((L - 20) / 60)
    L = mix(L, 100 * t^3 * (6*t^2 - 15*t + 10), c)
fy = (L + 16) / 116
rgb = clip(XYZ_TO_RGB @ (white * [fy + a/500, fy, fy - b/200]^3))

# 曝光曲线同时作用于向灰色混合后的 RGB 和灰色参考值
y = Y(rgb)
negative = min(0, e)
scale = 1 + negative / 16
gain = 10^(2*e)
curve(x) = x * gain / (1 + x * (gain - 1))
mixed = curve(scale * mix(rgb, y, 0.75))
chroma = 3 * (1 + y*y * negative / (0.2 - negative))
rgb = clip(mixed + (mixed - curve(scale * y)) * chroma)

# 减饱和向等亮灰色混合，增饱和按 RGB 边界限幅
y = Y(rgb)
s = clamp(saturation, -1, 1)
if s <= 0:
    k = 1 + s
else:
    limit = min(y / (y - min(rgb) + 1e-6),
                (1 - y) / (max(rgb) - y + 1e-6))
    k = min(2, mix(1, limit, s))
outputRGB = (y + (rgb - y) * k) ^ (1/2.2)
```

高光和阴影共用固定阈值 `0.5`，在亮度判断中用 `0.5^2.2 ≈ 0.217638`，在对比度中用 `L*=50`。Lab 转换直接用立方根和立方。调色保留采样的 Alpha。普通图片填充在调色后对 RGB 做 Alpha 预乘，再乘填充不透明度。

### 8 位 PNG 验证

用已有的 Figma 桌面端导出样本校验独立的浮点实现。普通四舍五入时，全 RGB 色卡的平均绝对误差是 0.02665 个色阶。根据该批样本的取整边界，可以用 `q = floor(clamp(encodedRGB, 0, 1) × 4096)` 和 `byte = (255 × q + 2047) >> 12` 复现本机 8 位 PNG 的量化。量化规则来自像素对比，着色器公式来自静态分析。

| Figma 导出样本 | 完全相同的 RGB 通道值 | 最大通道误差 |
| --- | ---: | ---: |
| 280 张单参数色卡，七个滑杆各测 40 档 | 27,524,106 / 27,525,120（99.9963%） | 1 |
| 红车七参设置，全部 16,777,216 个 8 位 RGB 输入 | 50,329,964 / 50,331,648（99.9967%） | 1 |
| 同一七参设置，红车原尺寸的 576,489 个不透明像素 | 1,729,462 / 1,729,467（99.9997%） | 1 |

红车原图和 Figma 导出的 Alpha 逐像素相同。量化误差统计覆盖本机 sRGB PNG 导出。Display P3、HDR 和其他显卡的输出量化尚未实测。
