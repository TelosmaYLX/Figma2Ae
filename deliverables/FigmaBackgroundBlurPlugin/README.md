实时复现 Figma「背景模糊」渲染算法的 AE 效果插件（C++ / AE SDK 27），支持 **均匀（uniform）** 与 **渐变（progressive）** 两种模式。

## 1. v1.7 的架构变化（区域跟随 + 渐变跟随）

**区域**（两种模型，二选一）：

- **调整层自己的遮罩（推荐）**：`Alpha源` 保持 **无**。在调整层上画一个和卡片一致的遮罩（如圆角矩形），AE 会用该图层的 alpha 裁剪效果输出——模糊只出现在遮罩内。调整层可以**直接父级到卡片层**，卡片位移/旋转/缩放时，遮罩跟着走。
- **Alpha源 图层（可选）**：把 `Alpha源` 设为某个图层，则用该图层的 **alpha 轮廓** 作区域（支持任意形状、带洞、文字等遮罩难以表达的情况），包围盒作 clamp。

两种模式都会按 Figma 语义把三角核采样**限制在区域包围盒内并重归一化**（卡片边缘不会吸进外面的颜色）。遮罩模式下包围盒由插件通过 AEGP 查询（`AEGP_GetLayerMaskedBounds` × layer-to-world 矩阵，实测该接口允许在 `PF_Cmd_RENDER` 里调用；`PF_InData.extent_hint` 恒为整帧，拿不到遮罩范围）。

**渐变线**：`渐变起点 X/Y (%)`、`渐变终点 X/Y (%)` 是 **模糊区域包围盒的百分比**（0–100），对应 Figma 的 `blurStartOffset/blurEndOffset`（0–1 归一化）。因为它是相对值：

> **卡片怎么动，模糊区域和渐变线都自动跟随，不需要给效果参数打任何关键帧。**
> 演示工程 `DEMO_Progressive` 就是这么搭的：只有卡片位置有关键帧，效果参数恒定。

为什么不用可拖的点参数（v1.6 的做法）：AE 里效果点在调整层上按 **comp 绝对坐标** 解释，实测把调整层整体位移 (+120, +80) 像素，渲染结果 **逐像素完全一致（差值 0）** —— 也就是说父级/位移不可能带动点参数，只有相对坐标才能跟随。

## 2. 两种模式与参数可用性

| 参数 | 均匀模式 | 渐变模式 |
|---|---|---|
| 模式 | ✔ | ✔ |
| 背景模糊半径 (px) | **✔ 可用** | 置灰 |
| 开始半径 (px) | 置灰 | **✔ 可用** |
| 结束半径 (px) | 置灰 | **✔ 可用** |
| 渐变起点 X/Y (%) | 置灰 | **✔ 可用** |
| 渐变终点 X/Y (%) | 置灰 | **✔ 可用** |
| 柔化边缘 (AA) | ✔ | ✔ |

置灰走 `PF_PUI_DISABLED`（`PF_Cmd_UPDATE_PARAMS_UI` + `PF_UpdateParamUI`），属于**界面性**变更、不入撤销栈；切换模式立即刷新。

## 3. 推荐工作流

1. 放好背景图层。
2. 在背景之上新建**调整层**，添加 `F2A 插件 → Figma 背景模糊`。
3. 给调整层画一个与卡片一致的**遮罩**（圆角矩形；也可以直接把卡片形状层的路径粘贴成遮罩），`Alpha源` 保持 无。
4. 把**调整层父级到卡片层**（或把两者放进同一父级），并让卡片层显示在调整层上方 —— 顺序与 Figma 一致：先模糊背景，再画半透明填充与描边。
5. 选择**模式**：均匀设 `背景模糊半径`；渐变设 `开始半径`/`结束半径`，渐变线默认是「包围盒上中 → 下中」，按需改百分比。
6. `柔化边缘 (AA)` 控制边缘硬/软语义（默认硬边 = Figma 的 discard 语义；遮罩模式下边缘本来就由 AE 的遮罩抗锯齿处理）。

## 6. 性能（v1.8 实测）

测试环境：AE 2026 / Windows 11 / AMD64，合成 1200×800，遮罩模式，渐变 0→40 px；
方法：插件内 `QueryPerformanceCounter` 逐阶段计时，24 个不同帧取平均（每次都是真实渲染，不吃缓存）。

| 阶段 | v1.7 | v1.8 |
|---|---|---|
| 复制背景 | 208 µs | 214 µs |
| 取遮罩范围（AEGP） | 83 µs | 84 µs |
| 计算每像素核数量 | 488 µs | 329 µs |
| 读入像素 | 388 µs | 300 µs |
| 水平通道（行） | 2,746 µs | 2,737 µs |
| 垂直通道（含合成） | 3,648 + 616 µs | 4,027 µs |
| **合计** | **8,177 µs（8.2 ms/帧）** | **7,691 µs（7.7 ms/帧）** |

v1.8 的结构性改动：

- 去掉不用的 alpha 平面、`Cgrid` 之外的三张整帧中间图（少分配 ~15 MB、少一次全帧往返）；
- 垂直通道按 **16 列分块** 处理，读写都变成连续地址（原来是按列跨行跳跃，每个像素一次 cache miss）；
- **合成/混合融合进垂直写回**，省掉一整帧的独立合成 pass；
- 均匀模式走常量 count 的快速路径（`cstride = 0`，零逐像素查表）；
- Release 打开 `/Oi` 与 `/GL` + LTCG。

输出与 v1.7 相比：均匀模式逐字节一致；渐变模式 960,000 像素里 34 个像素差 1 灰阶（渐变投影改成乘法倒数带来的舍入差，指标不变：0.045 / 0.101）。

**还有多少空间？** 单帧成本现在由两个卷积 pass 主导（6.7 ms / 7.7 ms），再往下压要靠换算法或向量化：

| 方向 | 预期收益 | 代价/风险 |
|---|---|---|
| SSE2/AVX2 向量化两个 pass 的求值循环（逐像素独立，天然可并行 4/8 路） | **1.5–2×**（≈4–5 ms/帧） | 需要 CPU 特性检测 + 边缘像素单独处理；中等工作量 |
| 三角核改用「盒⊛盒」两次盒式滤波 | 乘加再降一半 | Figma 的 clamp 是"重归一化用到的权重"而不是边缘复制，盒式推导边界要额外处理，有精度风险 |
| 每行 prefix 数组压进 L1 / 寄存器滚动和 | 10–20% | 循环结构改动大 |
| 插件内部多线程 | 近线性 | 不推荐：AE 已按帧并行（本插件已声明 MFR 线程安全），内部再开会超订 |
| AE 侧 Smart Render / 磁盘缓存 | 重复渲染几乎免费 | 无需改插件，属工程设置 |

结论：**1200×800 约 7.7 ms/帧，4K 约 9 倍（~70 ms/帧）**；常规 UI 动效（几百帧 1080p）用当前算法完全够用，MFR 打开后跨帧并行还会再快数倍。如果后续要冲 4K 逐帧实时预览，再上 SSE2 向量化最划算。

## 7. 已知限制 / 说明

- 效果必须放在**调整层**上（AE 滤镜只能拿到"下方合成"作为输入，拿不到宿主调整层自身的遮罩）。
- 遮罩模式下 `Alpha源` 必须留空（无）；选了 `Alpha源` 就走逐像素 alpha 区域。
- 渐变线段是**直线**（与 Figma 一致）；径向/角度渐变不在范围内。
- 遮罩需要是**不透明、无羽化**（羽化会让边缘变软；想要 Figma 的硬边请不要加羽化）。
- 8/16 bpc 原生支持；32 bpc 工程下 AE 以 16 bpc 渲染本效果。
- PiPL 名称/分类为 GBK 编码（中文 Windows 需 CP936）。
- **参数顺序在 v1.7 变了**（渐变的两个点参数换成四个百分比）：旧工程打开后 `Alpha源` 会变成 0（即遮罩模式），`柔化边缘` 也可能错位，重新设置一次即可。
- **撤销**：插件不调用任何撤销组 API（`AEGP_StartUndoGroup` 等），参数改动全部由 AE 宿主记录；AE 报「撤消组不匹配，将尝试修复」属于宿主撤销栈的自我修复提示，如出现请重启 AE 后再确认。

## 9. 版本历史

- **1.8**：性能重排（垂直通道 16 列分块、合成融合进写回、去掉多余中间图与未用 alpha 平面、/Oi+LTCG）；1200×800 由 8.2 ms 降到 7.7 ms/帧，输出与 1.7 逐字节近似（均匀一致，渐变 34/960000 像素差 1 灰阶）。
- **1.7**：区域改为「调整层自己的遮罩」（AE 裁剪，AEGP 取遮罩包围盒做 clamp），支持父级跟随；渐变改为区域包围盒百分比（自动跟随，无需关键帧）；按模式置灰无关参数；演示工程重建。
- **1.6**：渐变端点改为图层像素点（可在合成窗口拖点，但区域移动后不跟随，需打关键帧）。
- **1.5**：新增渐变（progressive）模式。
- **1.4**：中文参数名，PiPL 中文名 GBK 后处理。
- **1.3**：模糊区域改为由 Alpha 驱动（支持形状/遮罩/位移动画）。
