# AEP 目标版本选择

## 输入和格式

用户提供 `D:\AAA Work\2026\L50无限大\L50摇车牌\首页\首页 复制 24.x.aep`。只读解析确认其应用版本为 `24.6x65`，工程格式为 `95.6`；原 F2A 首页工程为 `26.0x67`、格式 `97.2`。

当前开发环境和已安装组件使用同一份 py-aep 0.19.0 版本规则；它在创建项目和图层时按目标版本选择结构。参考 [py-aep 版本规则源码](https://github.com/forticheprod/py-aep/blob/main/src/py_aep/ae_version.py)。F2A 之前将 `py_aep.new` 固定为 `26.0x67`，本次改为：

| 面板选项 | 数据值 | 创建版本 | 工程格式 |
| --- | --- | --- | --- |
| 24.x | 24.0 | 24.0x0 | 95.6 |
| 25.x | 25.0 | 25.0x0 | 96.9 |
| 26.x（默认） | 26.0 | 26.0x67 | 97.2 |

不修改用户提供的旧工程，也不依赖 AE 打开工程再另存。

## 实现

- 面板继续使用现有普通 HTML、深色变量、8 px 间距和圆角。版本选择放在导出按钮右侧，宽 88 px，采用 `--surface` 底色和 `--line` 边框；移除可见版本标签，保留无障碍名称。导入和导出按钮上下相邻。
- UI 导出锁包含版本选择；发送 `packet.aeVersion`。直接导入当前 AE 不发送该版本设置。
- `normalize` 检查目标版本，缺省保留 26.0；不支持的版本在保存窗口出现前报错。
- Python 从创建项目时选择目标版本，最终报告记下实际目标。
- 服务协议仍为 3，健康检查新增 `aeVersions`。面板核对能力，避免旧组件忽略选择后继续生成 26.x。

## 验证

`tests/aep-versions.cjs` 用生产写入链生成三个版本的基础工程和独立遮罩工程，共六份；原始 RIFX `head` 直接检查应用主版本和格式号，再用解析器核对图层、变换、透明度和遮罩关系。三个版本均运行已有独立图片遮罩检查，覆盖 alpha、luma、矢量遮罩、裁剪图片、嵌套内容和文字。

随后从此前真实首页的修复模型 `artifacts/home-backdrop-20261116/repaired-model.json` 分别生成三个目标版本。模型保留用户真实图形、图片和已修正的背景模糊底框。

AE 26.0x67 通过 `tests/ae-aep-versions.jsx` 逐份临时导入九份工程，核对文字、形状、轨道遮罩及素材完整性，并渲染一帧。检查结束清理导入项、恢复原活动合成和排队渲染状态。

- 九份工程均无缺失素材或导入错误。
- 基础工程各保留 3 个形状和 1 个原生文字层。
- 独立遮罩工程各读出 1 个原生文字层和 11 个遮罩关联。
- 真实首页三个版本均保留相同矢量内容和 3 个遮罩关联。
- 每类样本的 24.x、25.x 渲染与 26.x 基准 RGBA 逐像素一致，最大差为 0。
- UI 默认值、两个旧版选值传递、导出锁、旧组件能力拒绝和 HTTP 非法版本拒绝均通过；320/375/1280 宽预览无横向溢出，按用户截图调整的按钮和选择框布局已经目视检查。

证据在 `artifacts/aep-versions/`：`cases.json`、`native.json`、九份渲染和 `render-metrics.json`。布局预览在 `artifacts/export-options/ui-375.png` 和 `ui-1280.png`。

已同步当前用户安装目录中的面板、归一化模块、服务和 Python 写入器，重启空闲的本地 AEP 服务。实际服务公布三个版本；另外通过安装目录的 Node/Python 写入链生成一份 24.x 工程并再次核对原始格式，记录在 `installed-cases.json`。Figma 中重新打开 F2A 后加载新面板。

本机安装了 AE 26 和 CC 2019，没有 AE 24/25。因此已验证真实旧版格式及在 AE 26 中的内容一致性，未将这些结果描述为已经在 AE 24/25 软件中完成原生打开验收。
