# 直接导出 AEP（实验）

这一版将 F2A 数据包直接写成二进制 `.aep`。点击导出时，由已打开的 AE/F2A 面板启动本地组件；工程写入仍不调用 AE 建层。保存窗口内可选择位置并修改名称，生成同名文件夹，内含同名 `.aep`、`Assets/` 和 `report.json`；在 AE 中打开该 `.aep` 即可，不再打包 ZIP。

## 使用

分发目标为 Windows x64，工程面向 AE 2026。分发包已包含 Node、Python/Tk 与导出依赖，使用者无需另装运行环境，也无需联网安装依赖。

分发用户双击包内 `install.cmd`，组件安装到 `%LOCALAPPDATA%\F2A\AEP` 并注册当前用户的点击唤起入口。用包内 `cep-extension` 的文件更新 AE 中已有的 F2A 扩展，重新打开面板；在 Figma 中导入安装目录下的 `figma-plugin/manifest.json`。组件安装后不再依赖原解压位置。后续更新仍运行同一安装程序，它只停止并更新该安装目录内的组件进程。

构建分发包需要 Windows x64、Node.js、完整 Python（含 Tcl/Tk）与已准备好的 `.venv-aep`：

```powershell
node scripts/package-aep-service.cjs
```

结果在 `artifacts/F2A-AEP-Windows-x64/`，应完整分发该目录。构建过程会获取所用 Node 版本的许可证；安装与导出本身无需网络。Python 使用包内独立模块搜索路径，不引用构建机器的安装目录。`runtime-manifest.json` 记录版本与运行程序摘要，许可证随运行环境和依赖保留。

开发者直接在仓库中使用时，也可只注册开发目录的入口（机器需有 Node.js 18+、Python 3.11+）：

```powershell
powershell -ExecutionPolicy Bypass -File .\scripts\install-aep-launcher.ps1
```

入口使用 `f2a-aep://`，不添加开机启动项或登录任务。分发版记录当前设备安装目录内的运行环境路径；开发版记录本机 Node/Python 路径，开发目录或运行环境位置改变后需重新注册。

重新运行 Figma 开发插件，打开 AE 的 F2A 面板，选中内容并点击“导出 AEP（实验）”。服务未运行时，插件向 AE 面板的 `POST /aep/start` 请求启动；CEP 通过 Windows 唤起注册组件。服务就绪后先采集内容、处理图片并在临时目录生成完整 AEP，字体、素材和工程检查全部通过才弹出保存位置窗口。已运行时直接复用。每次导出无需手动运行脚本；AE 面板未打开、版本过旧、组件未安装或启动失败会分别提示。

启动器在后台运行本地服务 `127.0.0.1:7868`；分发版直接使用包内环境，开发版按需创建 `.venv-aep` 并安装固定依赖。重复唤起复用运行中的服务。服务使用 Tkinter 弹出原生保存窗口。日志位于安装或开发目录的 `artifacts/aep-service/`。

调试时仍可手动运行 `powershell -ExecutionPolicy Bypass -File .\scripts\start-aep-export.ps1`；加 `-Background` 在后台启动。关闭服务进程后，下一次点击导出会再次启动。卸载唤起入口可删除当前用户注册表中的 `HKCU\Software\Classes\f2a-aep`。

保存窗口默认使用选区名称，也可自行改名。例如在桌面输入“新工程”，会生成 `桌面/新工程/新工程.aep`。同名时文件夹和 AEP 名称加 ` (2)`、` (3)`，不覆盖旧工程。取消选择不会在目标位置创建文件，临时工程在取消、失败或保存完成后自动清理。导出成功后显示完整保存路径及“打开文件夹”按钮，点击后显示资源管理器窗口。

原“导入到 After Effects”按钮仍使用原通道。新增按钮复用同一组栅格化、分组、裁剪选项，并使用可编辑节点数据。合成默认为 30 fps、10 秒。

“切图倍率”默认 1×，可选 1×、2×、3×、4×，同时作用于导入 AE 和导出 AEP。倍率控制栅格化图层、投影及原图参考的 PNG 分辨率；AE 按对应倍率还原画面尺寸。普通图片填充继续使用原始素材，不随切图倍率重采样。

小数边界的切图使用对齐选区像素网格的透明画布，保留图形原始变换和小数偏移，避免 PNG 宽高分别取整改变比例及回放时再次过滤边缘。AEP 保留新建图层的默认质量与采样，不强制最佳质量或双三次采样。高级选项中的“双三次缩小（实验）”只处理图片文件，默认关闭。

也可从已经收集的 F2A 数据包生成工程：

```powershell
node scripts/export-aep.cjs packet.json output-directory
```

数据包的 `images` 各项包含原有图片元数据和 `data`（base64 图片）。`frame` 提供选区宽高，坐标保持 F2A 的画框相对坐标。CLI 直接写入指定的新输出目录，不弹目录窗口。`F2A_PYTHON` 可指定已有的 Python 环境。

## 可行性与取舍

| 方案 | 结论 |
| --- | --- |
| JSX 建层后保存 AEP | 沿用现有接口，但生成过程仍依赖 AE 逐层创建，不能解决本次目标 |
| 生成 AEPX | AE 官方支持 XML 工程作为自动化中间格式，但其中仍有二进制字段，不是普通 XML 模板即可完整生成 |
| 在 AE 外写二进制 AEP | 本分支采用；py-aep 0.19.0 提供项目、图层、素材和属性的写入接口，真实 AE 26 已验证能读取与渲染 |

依据：[Adobe 工程格式说明](https://helpx.adobe.com/after-effects/desktop/work-with-projects/after-effects-projects/projects.html)、[py-aep 源码与功能范围](https://github.com/forticheprod/py-aep)、[格式资料](https://forticheprod.github.io/py-aep/file_format/)、[库的已知限制](https://forticheprod.github.io/py-aep/limitations/)。依赖采用 MIT 许可证；本仓库仅固定并安装依赖，没有复制其源码。

流程为：点击导出 → 检查/启动服务 → Figma 采集节点和 PNG → 插件 UI 汇集并处理素材 → 本地 Node 服务复用 `svgParser` → Python 在临时目录生成完整 AEP → 检查通过后弹出目录选择窗口 → 保存工程及素材 → 清理临时目录并显示路径与“打开文件夹”按钮。AE 面板负责进程启动，Node 和 Python 不调用 AE 建层。启动入口只执行固定命令，不接收请求中的 URI、脚本或路径。

当前 Figma 桌面客户端的外部链接白名单不包含 `f2a-aep:`；直接使用 `figma.openExternal` 会在组件启动前被拒绝。原先测试替换了该宿主方法，因此没有覆盖这项限制。现在由具备 Node 进程接口的 CEP 执行 Windows 协议唤起，仍沿用 [Windows URI 协议注册方式](https://learn.microsoft.com/en-us/previous-versions/windows/internet-explorer/ie-developer/platform-apis/aa767914(v=vs.85))；安装路径由当前设备注册表解析。

服务协议版本为 3：`POST /export` 接收 `{packet}`，完成工程生成和检查后调用原生保存窗口；取消返回 `{cancelled:true}`，保存成功返回 JSON 路径、报告及 `exportId`。`POST /open-directory` 接收 `{exportId}`，只打开本服务记录的成功导出目录，不接受任意路径。旧的提前选目录接口已移除。命名使用 Python 标准库的 `asksaveasfilename`，返回目标文件夹名称，不在窗口阶段创建文件。

## 范围

已实现：

- 图片素材、透明度、旋转、FIT/FILL、图片轮廓裁剪与隐藏原图参考层。
- 可编辑形状路径、矩形、椭圆、纯色/线性/径向渐变；闭合形状及文字的纯色描边使用图层样式，支持内部、外部和居中位置。开放线条、虚线及渐变描边保留路径绘制。
- 可编辑文字、富文本样式、段落行距/缩进/间距、字距、旋转和文字倾斜；渐变文字通过原生形状和文字遮罩实现。
- 文字整体、纯色填充与富文本各段透明度分别写入；父组透明度不重复乘到子文字。富文本透明度使用原生文字范围选择器，渐变填充自身的透明度单独保留。
- 形状、文字、图片、蒙版和预合成锚点居中，并补偿位置以保持画面不动；文字保留 AE 原生连续栅格化标志，确保 AE 读取正确的文字内容边界。
- Figma 栅格 PNG 保留所选切图倍率，默认 1×；1×、2×、3×、4× 素材分别使用 100%、50%、100/3%、25% 缩放，不再按带小数的边界做 FIT。普通图片填充继续按 FIT/FILL 换算。
- 分组预合成、绘制顺序、容器透明度、常用混合模式、矩形/圆角画框裁剪，以及节点的 alpha/luma 蒙版。
- 文件夹内的素材相对路径；文件生成无需 AE 面板或目标合成。

当前限制：

- 模糊、未烘焙的投影/内阴影等图层效果尚未原生写入；虚线尚未覆盖。AEP 专用采集在“模糊、阴影和特殊效果”开启时处理这些效果；直接传入未经处理的数据仍会报错。插件会先提取独立投影；直接传给 CLI、未经提取的 `shadowBase` 图片仍会报错。
- 字体及字重需本机可用；缺失字体、样式不符或无法计算文字排版时直接报错，不再替换字体继续输出。
- 图片填充的复杂裁剪、组合蒙版、多区域亮度/透明度和多种效果叠加尚未做到全面视觉验证。已经识别出的不支持组合会报错；成功生成文件不代表完成了像素对照。
- 当前固定生成 AE 26 工程；旧版 AE 和 macOS 未验证。不能承诺与 Figma 像素一致。
- py-aep 的写入仍是实验能力，不能只依靠它回读自身生成的文件判断正确性。例如本次发现矩形内部位置在库回读时正确，而 AE 实际读成零；本分支改用图层位置，并以真实 AE 属性断言覆盖。

## 自动处理范围

“高级选项 → 允许自动转为图片”有五个独立选项，默认开启；不再提供“自动栅格化不支持的内容”总开关。

| 选项 | 实际控制范围 |
| --- | --- |
| 模糊、阴影和特殊效果 | 投影、内阴影、图层模糊、背景模糊、玻璃、噪点、纹理、着色器。投影优先单独提取；AEP 不支持的其余效果连同所在图层渲染。普通 AE 导入仍可保留其已支持的原生效果。 |
| 特殊填充与描边 | 角度/菱形渐变、视频静帧、图案、着色器。普通纯色、线性/径向渐变和普通图片仍使用原有可编辑通道。容器上的特殊填充若无法单独处理，会点名属性并提示手动标记整个容器。 |
| 图片裁剪 | 无独立蒙版的图片使用 CROP 或自定义 imageTransform 时，固定该图片节点的外观。独立蒙版中的图片仍保留原图及裁剪变换。图片效果由第一项控制。 |
| 复杂蒙版 | 无法原生还原的渐变、图片、带效果蒙版及复杂遮罩范围。含图片且选择分离时，只渲染蒙版本身；其他无法原生转换的范围可能连同被遮罩内容一起渲染。 |
| 布尔运算结果 | 仅在 Figma 未提供 fillGeometry 结果路径时，渲染布尔节点；有结果路径时保留矢量。 |

这五项是转图的触发条件，不是强制处理所有同类图层。关闭某项后，如该内容无法原生还原，导出前会显示具体原因、对应选项和原图层定位。按图层渲染会固定该层的所有填充与效果；效果设置在组上时可能包含组内文字和图形。手动 `*`、强制整体转图、混合模式合并和明确选择“图片蒙版 → 合并成图片”仍遵循各自设置。

普通图片填充不触发父组合并。FIT/FILL 图片保留独立素材层；CROP 或本层效果需要烘焙时，仅渲染该图片节点。手动 `*` 标记、Group 整组栅格化和实例整体栅格化仍按用户指定的边界处理。

导出副本中的实例先从外向内自动分离，再处理内部蒙版、效果和裁剪，避免 `isMask` 无法覆盖的实例属性错误。分离后的 Frame 及子节点仍关联原图层 ID；原文件的实例关系不变，“实例整体栅格化”选项继续生效。分离顺序依据 [Figma detachInstance API](https://developers.figma.com/docs/plugins/api/InstanceNode/#detachinstance)，防止处理嵌套实例时连带分离祖先。

开启“模糊、阴影和特殊效果”时，背景模糊所在对象直接通过 Figma 导出为独立 PNG，保留其效果交给 Figma 渲染；不再因背景依赖直接拒绝，也不为此合并父组或背后的图层。该对象已有投影会一并写入这张 PNG，避免重复生成。关闭该项时会提示开启，并提供出错图层定位。

布尔运算优先使用节点的结果路径；没有结果路径且允许“布尔运算结果”转图时，只栅格化布尔节点。投影单独提取，背景、文字和其他图形继续保留；AEP 界面在生成工程前使用 Canvas 完成纯投影 PNG 的提取，失败时中止。AEP 专用采集将带模糊、内阴影等未支持效果的对象（包括分组和文字）单独栅格化，保留其范围之外的可编辑内容；关闭对应选项时提示开启，并提供定位。普通 AE 导入仍可使用原生预合成效果。

开启自动处理时，普通纯色 alpha/luma 蒙版优先保留原生遮罩。组内容的蒙版放在预合成上，不重复施加到每个子层。复杂图片、渐变或效果蒙版仅渲染该蒙版及受其遮罩的内容；父容器的背景、效果和其他兄弟层不进入这张图片。作用范围在同级的下一个蒙版或裁剪容器处停止；普通组内部另有蒙版时，保留内外两层关系，组内蒙版不会结束组外蒙版。相关层级和叠放规则参见 [Figma 蒙版文档](https://help.figma.com/hc/en-us/articles/360040450253-Masks)。

“图片蒙版”默认选择“原图 + 独立蒙版”，也可选择“合并成图片”。分开保留时，包含图片的蒙版范围保留原始图片素材，使用独立的 AE Alpha／亮度轨道遮罩；简单矢量蒙版保留形状，图片及复杂蒙版只单独渲染蒙版本身。图片自身的裁剪放入预合成，外部 Figma 蒙版施加到预合成上。CROP 保留原图及缩放、位置、旋转变换，暂不支持裁剪倾斜。该选项同时用于直接导入 AE 和导出 AEP；手动 `*`、Group 或实例整体栅格化仍按指定边界合并。

一个独立蒙版作用于多个兄弟层时，将这些内容放入同一个“蒙版名称 内容”预合成，再施加一次外层轨道遮罩。内部各组及局部蒙版继续保留，预合成范围包括内容的效果溢出。该结构需要开启“保留分组层级”；关闭时提示开启。结构仅在导出数据中生成，原 Figma 图层不重组。

混合模式合并会保留与后续混合内容不相交的普通图形、图片和文字，不再因为它们处于合并区间中就一起烘焙。蒙版和手动栅格化边界不被跨越。

图片读取/渲染失败、缺失素材、无效蒙版和路径解析失败都会中止本次导出。AE 桥接会丢弃未完成的图片批次；AEP 发现上述缺失或不支持的属性时不生成 `project.aep`，临时 packet 会清理。界面直接显示原因；有原图层 ID 的 AEP 校验和写入错误显示“定位图层”，按 ID 选中并缩放到原 Figma 对象。

## 验证

```powershell
node tests/direct-aep.cjs
node tests/direct-aep-ui.cjs
node tests/aep-launcher.cjs
node tests/raster-scope.cjs
node tests/aep-fidelity.cjs
node tests/aep-distribution.cjs
node scripts/verify-direct-aep.mjs
```

第一条使用实际 F2A 采集代码，Figma 场景 API 和 PNG 渲染由测试模拟，生成真 AEP 文件夹，检查目录取消、中文及空格路径、名称清理、同名不覆盖、不产生 ZIP 与 HTTP 错误。HTTP 检查模拟目录窗口返回值，不弹出交互窗口。UI 检查执行实际 iframe 代码，覆盖通过 AE 面板只启动一次、就绪后才采集、启动超时、离线/旧版面板、缺少组件及系统拒绝后释放按钮；同时检查已运行时复用、目录取消、图片分片、保存路径与错误提示。`aep-launcher.cjs` 使用实际 CEP 客户端回调和 HTTP 服务，模拟进程 API，检查固定协议、隐藏启动、当前用户注册项及启动错误。

范围检查覆盖多张独立位图、选中边界、原生/回退布尔、原生/局部蒙版、裁剪边界、父容器样式隔离和异常恢复。AEP 检查通过实际采集生成二进制工程，验证原生组遮罩与独立图片，并确认路径/素材缺失及不支持属性报错后不生成工程。Figma 渲染为模拟，未进行本轮真实 Figma 与 AE 画面对照。

分发检查将组件复制到中文新路径，在 PATH 中移除 Node/Python，并将 PYTHONHOME/PYTHONPATH 指向无效目录；核对 Python 的模块与 Tcl 库来源均为分发包，实际启动包内服务并生成真 AEP 文件夹。本机系统协议检查也确认冷启动和重复唤起成功，复用同一服务进程。尚未在第二台实机或干净 Windows 虚拟机上运行，也未完成真实 Figma 客户端点击唤起的端到端检查；不能把环境隔离测试表述为第二台设备的实测。
